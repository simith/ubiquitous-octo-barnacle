# 4. Connect an AI Client

Your MCP Server is deployed. The final step is to connect an MCP-compatible AI client.

The source tutorial demonstrates:

- Joule Work Desktop
- Claude Desktop

Both use the MCP URL and OAuth2 credentials created earlier.

---

## 4.1 Connect Joule Work Desktop

Open Joule Work Desktop.

Navigate to:

**Extensions → Add MCP Server**

Enter:

| Setting | Value |
|---|---|
| MCP Server URL | Your deployed MCP URL |
| Auth Type | `OAuth2` |
| Token URL | `tokenurl` from the service key |
| Client ID | `clientid` from the service key |
| Client Secret | `clientsecret` from the service key |

Select **Connect**.

The MCP Server should appear in the Extensions list with:

```text
Status: Active
```

The tools exposed by the MCP Server are then available to Joule.

You can ask Joule questions that require the connected backend data, and Joule can invoke the MCP tools to retrieve that information.

---

## 4.2 Connect Claude Desktop

Claude Desktop can connect through its MCP configuration file.

### macOS

```text
~/Library/Application Support/Claude/claude_desktop_config.json
```

### Windows

```text
%APPDATA%\Claude\claude_desktop_config.json
```

Add your server under `mcpServers`:

```json
{
  "mcpServers": {
    "<your-server-name>": {
      "type": "streamable-http",
      "url": "<your MCP URL>",
      "headers": {
        "Authorization": "Bearer <access-token>"
      }
    }
  }
}
```

Save the file and restart Claude Desktop.

Open a new Claude conversation and select the tools icon to verify that the MCP tools are available.

You can now ask Claude to use those tools to query your backend.

> The tutorial notes that the Bearer token can be generated by calling the OAuth2 token endpoint with the credentials from the service key.

---

## Important: don't commit tokens

Do not put real tokens, client secrets or API keys in:

- `claude_desktop_config.json` committed to Git
- README files
- screenshots
- issue comments
- pull requests

Use placeholders in documentation.
